# 河南科技大学本科毕业设计（论文）完整生成系统

## 概述

本 skill 定义了河南科技大学本科毕业设计说明书（论文）的完整格式规范与生成流程。它不仅能检查和指导论文格式，更能基于用户提供的毕业设计项目仓库，自动分析项目内容、研究相关技术背景、生成图表，最终输出一份内容充实、格式合规的完整 Word 论文文档。

## 各部分详细格式

### 1. 封面

- 第一行：学校英文全称 `HENAN UNIVERSITY OF SCIENCE & TECHNOLOGY`，居中
- 中间：`毕 业 设 计（论 文）`（字间有空格），大号字居中
- 论文题目：黑体，三号(16pt)，**加粗**（批注[1]）
- 信息字段：宋体，小三号(15pt)，不加粗，居中（批注[2]）
- 底部：日期 `[年份] 年 [月] 月 [日] 日`，居中

### 2. 学位论文写作声明 + 使用授权说明

固定格式，包含两个声明，留签名栏和日期栏。无页眉页脚。声明标题为黑体小二号(18pt)，内容为宋体小四号(12pt)。

### 3. 中文摘要

- 页眉：`河南科技大学毕业设计说明书（论文）`
- 论文题目：三号黑体(16pt)，居中
- "摘  要"标题：三号黑体(16pt)，居中，字间空一格，上下空行为小四号字大小（批注[6][7][8]）
- 正文：小四号宋体(12pt)，首行缩进2字符
- "关键词："标签：小四号黑体(12pt)，首行缩进2个字符；其后关键词为小四号宋体(12pt)，中文分号分隔

### 4. 英文摘要

- 页眉：论文英文题目（全部大写）
- 论文题目：三号 Times New Roman(16pt)，全部大写，居中，**加粗**（批注[12]）
- "ABSTRACT"标题：三号 Times New Roman(16pt)，全部大写，居中，**加粗**（批注[14]）
- 正文：小四号 Times New Roman(12pt)，**每段开头留四个字符空格**（批注[16]）
- KEY WORDS：小四号 Times New Roman(12pt)大写，关键词用小四号小写，英文分号分隔，分号后加一空格，最后一个关键词后不打标点（批注[17]）

### 5. 目录

标题"目  录"，三号黑体(16pt)，居中。目录内容为宋体小四号(12pt)。前导符用短实线。逐级缩进：一级标题左对齐，二级缩进0.25字符，三级缩进1.5字符（批注[18]）。使用 TOC 域代码，用户在 Word 中右键"更新域"即可自动生成。

### 6. 正文

- 章标题格式：`第X章 [章名]`，三号黑体(16pt)，**不加粗**，居中，另起一页，章标题后空行为三号字大小（批注[19]）
- 节标题格式：`X.Y [节名]`，四号黑体(14pt)，**不加粗**，顶格书写，**段前0.5行，段后0.5行**，序号与文字中间空一格，标题末尾不加句号（批注[20]）
- 子节标题格式：`X.Y.Z [子节名]`，小四号**宋体**(12pt)，**不加粗**，顶格书写，**段前0.5行，段后0.5行**，序号与文字中间空一格，序号也是宋体（批注[22]）
- 四级标题格式：`X.Y.Z.W [名]`，小四号宋体(12pt)，不加粗，顶格书写
- 正文：小四号宋体(12pt)，**单倍行距**，首行缩进2字符

**图片格式**：编号 `图X-Y [图名]`，位于图下方居中，五号楷体(10.5pt)，需在正文中引用。

**表格格式**：编号 `表X-Y [表名]`，位于表上方居中，五号楷体(10.5pt)。表格采用三线表样式，表头用五号黑体加粗，表内文字用五号宋体。需在正文中引用。

## 完整论文生成工作流

当用户提供毕业设计项目仓库并要求生成完整论文时，按以下步骤执行。

### 阶段一：收集信息

向用户收集以下信息（已有则跳过）：

1. **论文题目**（中文 + 英文）
2. **个人信息**：姓名、学院、专业、指导教师
3. **完成日期**
4. **项目仓库路径**（本地路径或 GitHub URL）
5. **参考资料**（可选）：
   - 往年论文范例目录（如 `往年论文范例/`，包含 PDF 参考论文）
   - 论文规范目录（如 `论文规范/`，包含学校官方撰写规范文档）
   - 如存在这些目录，先读取其中的文件以获取更精确的格式要求和写作风格参考

### 阶段二：项目分析

使用文件系统工具深入分析项目仓库，提取以下信息：

**技术栈识别**：
- 扫描 `package.json`、`requirements.txt`、`Pipfile`、`pyproject.toml`、`pom.xml`、`build.gradle` 等依赖文件
- 识别编程语言、框架、数据库、中间件
- 查看 `README.md`、配置文件了解项目架构

**功能模块提取**：
- 分析源码目录结构，识别模块划分
- 读取路由文件（如 `urls.py`、`router.js`、`controllers/`）了解功能端点
- 分析数据库模型文件（如 `models.py`、`schema.prisma`、`entities/`）

**数据库设计提取**：
- 从 ORM 模型文件中提取表名、字段名、字段类型、关联关系
- 识别主键、外键、索引等约束

**核心逻辑分析**：
- 找到项目的核心算法/业务逻辑代码
- 提取关键函数和类的功能描述

### 阶段三：网络研究

对论文中需要研究性叙述的部分进行网络搜索：

**国内外研究现状**（第1章 1.2节）：
- 搜索项目所用的核心技术的起源和里程碑论文（如 RAG → Lewis 2020、BERT → Devlin 2019）
- 搜索国内外同类系统的研究和应用现状
- 将搜索到的关键信息整理为参考文献条目（GB/T 7714 格式）

**技术背景**（各章节技术选型部分）：
- 搜索所用框架/库的官方文档和版本信息
- 验证技术描述的准确性

**参考文献要求**：
- 数量不少于 15-20 篇
- 包含中英文文献
- 以期刊论文[J]、会议论文[C]为主，辅以专著[M]和电子文献[EB/OL]
- 每篇文献必须在正文中以上标形式引用

### 阶段四：图表规划与生成

根据项目特点，规划并生成以下图表（使用 Mermaid CLI）：

**规划原则**：
- 根据项目实际情况灵活选择图表类型和数量，不拘泥于固定模板
- 每个系统至少需要：架构图、ER图、核心流程图
- 图表编号格式：`图X-Y`，X为章号，Y为该章内顺序号

**Mermaid 图形生成流程**：

1. 编写 Mermaid 语法文本（`.mmd` 格式），保存到 `diagrams/` 目录
2. 使用 `mmdc` CLI 渲染为 PNG：
   ```bash
   mmdc -i diagram.mmd -o diagram.png -b white \
     -p diagrams/puppeteer-config.json -s 2
   ```
3. `puppeteer-config.json` 内容（在 Linux/root 环境必须）：
   ```json
   {"args": ["--no-sandbox", "--disable-setuid-sandbox"]}
   ```
4. 使用 python-docx 的 `run.add_picture()` 插入 Word 文档
5. 在图片下方添加图注（五号宋体，居中）

**常见图表类型**：

| 图表类型 | Mermaid 语法 | 适用章节 | 说明 |
|----------|-------------|----------|------|
| 系统架构图 | `graph TB` + `subgraph` | 第3章 3.1 | 展示系统分层架构 |
| ER图 | `erDiagram` | 第3章 3.3.1 | 数据库实体关系 |
| 功能模块图 | `graph TD` | 第3章 3.2 | 系统功能模块结构 |
| 流程图 | `graph LR/TD` | 第4章 | 核心业务流程 |
| 序列图 | `sequenceDiagram` | 第4章 | 交互流程（可选） |

### 阶段五：论文内容撰写

基于项目分析结果和网络研究资料，撰写各章节内容。

**写作要求**：
- 内容基于项目实际情况，不编造虚构内容
- 学术论文风格，用语严谨、表述准确
- 每章字数合理：绪论约3000字，需求分析约2000字，系统设计约3000字，系统实现约3000字，系统测试约1500字
- 研究现状部分需引用真实文献，通过网搜验证
- 技术描述需与项目代码一致

**上标引用规则**（非常重要）：
- 使用专用函数 `add_cited_para(doc, text)` 而非 `add_body_para(doc, text)`
- 在文本中用 `^{[N]}` 标记引用：`"Lewis等人^{[1]}提出了RAG框架"`
- 两个函数绝对不可混用：`add_body_para` 中出现 `^{[N]}` 会原样输出为纯文本
- 每篇参考文献至少被引用一次
- 引用集中在：绪论研究现状、系统设计技术选型、系统实现技术细节

### 阶段六：文档生成

使用 python-docx 生成 Word 文档，关键技术要点：

#### 标题样式（目录依赖此配置）

必须使用 Word 内置标题样式（Heading 1/2/3），否则目录无法生成。

在文档创建后、写入内容前配置样式：
- `Heading 1`（一级标题/章标题）：黑体，三号(16pt)，**不加粗**（`bold=False`），居中，黑色(`RGBColor(0,0,0)`)，分页符前置
- `Heading 2`（二级标题/节标题）：黑体，四号(14pt)，**不加粗**，顶格书写(左对齐)，黑色
- `Heading 3`（三级标题/子节标题）：**宋体**（非黑体！），小四号(12pt)，**不加粗**，顶格书写，黑色
- 颜色必须显式设为黑色（Word 默认标题为蓝色/紫色）
- 东亚字体需通过 XML 设置 `w:rFonts` 的 `w:eastAsia` 属性
- **字体名必须使用英文标识符**：`SimHei`（非'黑体'）、`SimSun`（非'宋体'）、`KaiTi`（非'楷体'），避免在 Linux/WSL 环境下被映射为 MS Gothic 等错误字体
- **关键：黑体本身就是粗体字形，不需要额外设置 bold=True。示例文档中所有标题的 bold 属性均为 None(inherit)**

```python
# 正确用法
para = doc.add_paragraph('第1章 绪论', style='Heading 1')
para.paragraph_format.first_line_indent = Emu(0)

# 错误用法（目录无法识别）
para = doc.add_paragraph()
run = para.add_run('第1章 绪论')
run.font.bold = True  # 仅手动格式化，不绑定样式
```

#### 主题字体覆盖问题（MS Gothic 替换 SimHei）

**问题**：在 WSL2/Linux 环境下用 python-docx 设置 `w:eastAsia="SimHei"` 后，生成的 Word 文档中黑体仍显示为 MS Gothic。

**根本原因**：python-docx 创建标题样式时，Word 会在 XML 的 `w:rFonts` 元素上自动添加主题字体引用（如 `w:eastAsiaTheme="majorEastAsia"`、`w:asciiTheme="majorHAnsi"`）。这些主题字体属性的**优先级高于**显式设置的 `w:eastAsia="SimHei"`，导致自定义字体被主题字体覆盖。

**解决方案**：在设置自定义字体后，必须清除所有 `*Theme` 属性：

```python
from docx.oxml.ns import qn

def _clear_theme_fonts(rFonts):
    """清除 rFonts 元素上的主题字体引用，防止覆盖显式字体设置"""
    for attr in ('eastAsiaTheme', 'asciiTheme', 'hAnsiTheme', 'cstheme'):
        rFonts.attrib.pop(qn(f'w:{attr}'), None)
```

**使用时机**：每次通过 XML 设置字体（`rPr.rFonts`）后，都必须调用此函数清除主题字体。包括：标题样式配置、正文 run 字体设置、页眉页脚字体设置等所有涉及 `w:rFonts` 的场景。

#### 居中对齐被覆盖问题（通用）

**问题**：图注、表题、摘要标题（"摘  要"）、英文摘要标题（"ABSTRACT"）、目录标题（"目  录"）、中英文论文题目等需要居中的段落，设置了 `CENTER` 对齐后仍显示为两端对齐（JUSTIFY）。

**根本原因**：`set_para_format()` 等段落格式辅助函数的 `alignment` 参数默认值为 `JUSTIFY`（两端对齐）。如果先单独设置 `p.alignment = CENTER`，再调用 `set_para_format(p, ...)` 而未传入 `alignment` 参数，则 `JUSTIFY` 默认值会**覆盖**之前的 `CENTER` 设置。

**受影响场景**（所有需要居中但未使用 Heading 样式的段落）：
- 中文摘要页的论文题目、"摘  要"标题
- 英文摘要页的英文题目、"ABSTRACT"标题
- 目录页的"目  录"标题
- 图注（"图 X-Y ..."）
- 表题（"表 X-Y ..."）

**解决方案**：不要在 `set_para_format()` 之前单独设置对齐方式。改为在调用 `set_para_format()` 时显式传入 `alignment` 参数：

```python
# 正确用法：在 set_para_format 中传入 alignment=CENTER
set_para_format(p, alignment=WD_ALIGN_PARAGRAPH.CENTER, first_indent=Emu(0))

# 错误用法：先设 CENTER，再被 set_para_format 的默认 JUSTIFY 覆盖
p.alignment = WD_ALIGN_PARAGRAPH.CENTER
set_para_format(p, first_indent=Emu(0))  # alignment 默认 JUSTIFY，覆盖了 CENTER
```

**注意**：使用 Heading 1 样式的标题（如"第X章"、总结与展望、致谢）不受此影响，因为 Heading 1 样式本身已在 `configure_styles()` 中配置了居中对齐，样式属性的优先级高于段落直接格式。

#### 上标引用实现

```python
import re

def add_cited_para(doc, text, indent=True):
    para = doc.add_paragraph()
    pattern = r'\^\{(\[[^\]]*\])\}'
    parts = re.split(pattern, text)
    for i, part in enumerate(parts):
        if not part:
            continue
        run = para.add_run(part)
        set_run_font(run, cn_font='宋体', size=Pt(12))
        if i % 2 == 1:  # 奇数位是 ^{[N]} 匹配的引用文本
            run.font.superscript = True
    return para
```

## 检查已有论文时

当用户要求检查/校对论文格式时，逐项核对以上规范，重点关注：
- 章节编号是否一致
- 页眉是否正确交替
- 页码是否正确（罗马 vs 阿拉伯）
- 图表编号格式是否为"图X-Y"/"表X-Y"
- 参考文献是否符合 GB/T 7714 格式
- 关键词分隔符是否正确（中文用"；"，英文用";"）
- 标题是否使用了 Word 内置标题样式（Heading 1/2/3）
- 正文中是否有上标引用标注，且每篇参考文献都至少被引用一次
- 图表是否在正文中被引用（如"如图3-1所示"）
